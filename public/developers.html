Drew API

Configure Drew from code or let an AI set up your server — no dashboard needed. Every change is validated, audited and announced in your log channel.

Quick start View the schema

Scoped

One token, one server

read, write or admin; expiring and revocable from Discord.

Self-describing

Machine-readable schema

Types, allowed values, ranges and whether each setting is enforced.

Safe

Dry runs & audit log

Preview every change; nothing applies unless the whole patch is valid.

Step 1

Create a token in your server

/api token create name:claude-setup scope:write expires:7
  • Requires Administrator plus being the server owner or having an active /sudo session.
  • admin tokens (which can edit anti-nuke whitelists) can only be created by the owner.
  • The token is shown once, only to you. Drew stores only its hash. Revoke it with /api token revoke.

Step 2

Preview, then apply a change

curl -X PATCH https://api.drewbot.xyz/api/v1/guilds/$GUILD_ID/settings \
  -H "Authorization: Bearer $DREW_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "settings": {
      "anti_nuke_enabled": true,
      "nuke_punishment": "ban",
      "channel_delete_limit": 3,
      "log_channel_id": "234567890123456789"
    },
    "dry_run": true
  }'
{
  "guild_id": "123456789012345678",
  "dry_run": true,
  "applied": false,
  "changes": {
    "nuke_punishment": { "old": "none", "new": "ban" }
  },
  "settings": { "...": "current settings" }
}

Send the same request with "dry_run": false to apply it. Discord IDs are always strings.

For AI agents

Paste this into your assistant

You can configure my Discord server's Drew bot through its API.
Base URL: https://api.drewbot.xyz/api/v1
Token: (read it from the DREW_TOKEN environment variable; never print it)

1. GET /me to learn the server ID.
2. GET /schema and GET /guilds/{id}/settings, /channels and /roles.
3. Propose changes using only settings with "enforced": true.
4. PATCH /guilds/{id}/settings with "dry_run": true and show me the changes.
5. Only after I confirm, send the same PATCH with "dry_run": false.

Security

How your server stays safe

  • Tokens are random 256-bit secrets, stored hashed, scoped to one server, time-limited and revocable.
  • Channel and role references are checked against your server; @everyone and bot roles can't be whitelisted.
  • The SUDO password and internal fields are never readable or writable.
  • Every change is attributed in /audit and posted to your log channel.
  • Rate limits: 120 reads and 30 changes per minute per token.
